# 第一部分：产品需求说明书（PRD）

## 1. 背景与问题

制造/电缆等 ToB 销售场景里，跟进链条长、资料散（规格书、报价历史、合同）、客户沟通集中在 **企业微信**。现有方式依赖人工回复与催办，响应慢、标准不统一、知识难以复用。

市场上的开源 Agent 平台（如 Dify）星数高，但 **License 限制多租户 SaaS 与去品牌**，无法直接「换皮封装成自己的产品」对外卖。需要一套：

1. **可白标、可多租户商用** 的软件授权路径；  
2. **工厂式** 搭建能力（可视化 Agent + 工作流 + 工具）；  
3. **企微原生** 触达，能跑催客户、自动回复、询价报价等全流程；  
4. 既能 **SaaS 订阅**，也能后续 **私有化交付**。

## 2. 产品愿景

> 让实施方或客户在「工厂」里搭建机器人，一键挂到企微/飞书；机器人既能被人调用，也能按组织规则 **主动** 推进复杂、长程任务（催办、跟进、升级、转人工），调用知识库与业务工具，在组织内把事做完。同一套能力以白标 SaaS 卖给多家企业，并支持按客户私有化部署。

**不是：** 单一聊天机器人、个人助理壳（Grok / OpenClaw 类「人喊一句才动」）、或不可商用的开源换皮。  
**是：** 行业 **组织级 AI 员工** 的生产与运营平台（模板 × 租户 × 渠道 × **主动任务**）。

### 2.1 与个人 Agent 的本质区别

| | 个人 Agent（Grok / OpenClaw 等） | 本产品（组织 Agent 工厂） |
|--|----------------------------------|---------------------------|
| 驱动方式 | 多为个人召唤或个人日程 | **组织规则 + 事件 + 定时** 也可驱动 |
| 任务形态 | 帮我干一件事 | **长程任务**：多日催办、跨人升级、可审计 |
| 信任域 | 个人/小团队单网关 | 多租户隔离、组织内权限 |
| 入口 | 私聊为主 | 企微/飞书：**可人工调用，也可无人值守推进** |

## 3. 目标用户与角色

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| 平台方（你们） | 运营 SaaS、做行业模板、签单交付 | 可复制交付、可控成本、可白标 |
| 租户管理员 | 客户公司 IT/老板指定管理员 | 开户、品牌、渠道、权限、用量 |
| 业务搭建者 | 销售运营 / 实施顾问 | 用模板或画布搭流程、接知识库与工具 |
| 一线销售 | 企微里使用 Bot | 少操作、准回复、自动催办 |
| 外部客户（终端） | 在企微与机器人/销售会话 | 快速得到报价与答复 |
| 平台超管 | 你们内部 | 租户开通、封禁、全局监控 |

## 4. 使用场景（User Stories）

### 4.1 工厂搭建

- 作为搭建者，我希望用可视化方式创建「询价报价」工作流，以便不写代码也能改话术与分支。  
- 作为搭建者，我希望上传规格书/历史报价到知识库，以便回复时有依据并可溯源。  
- 作为搭建者，我希望把工作流发布成 Bot，并绑定企微机器人，以便客户在企微里直接用。

### 4.2 企微全流程运营

- 作为销售，当客户在企微询价时，Bot 应检索知识库并生成报价草稿或专业答复。  
- 作为销售，当客户超时未回复时，系统应按策略自动催办（可配置话术与间隔）。  
- 作为销售，当 Bot 不确定或涉及价格承诺时，应转人工并保留上下文。  
- 作为管理员，我希望查看会话与用量，以便控制成本与质量。

### 4.3 SaaS 多租户与白标

- 作为平台方，我希望每个客户是独立租户，数据与渠道互不可见。  
- 作为租户管理员，我希望替换 Logo、名称、主题色（及自定义域名），以便对外是我们品牌。  
- 作为平台方，我希望按套餐限制 Bot 数、消息量、存储，超额可拦截或告警。

### 4.4 商业化

- 作为平台方，我希望用行业模板 30 分钟内为新客户上线一个企微 AI 员工。  
- 作为平台方，我希望软件订阅费与模型调用费分开展示，以便保护毛利。

## 6. 核心用户流程

### 6.1 租户开通到 Bot 上线

```
平台开通租户 → 管理员登录控制台 → 配置白标
  → 创建/选择模板「询价报价」
  → 上传知识库文档（RAGFlow）
  → 在 Coze 中确认/微调工作流并发布
  → 绑定企微机器人凭证
  → 测试会话通过 → 标记上线
```

### 6.2 运行时消息链路

```
企微用户发消息
  → 渠道网关验签 / 长连接事件
  → 解析 corp/bot → 映射 tenant_id（严禁串租）
  → 检查租户配额与 Bot 状态
  → 调用 Coze 对话或工作流 API
       ├─ 需要知识：查 RAGFlow（带租户隔离）
       ├─ 需要工具：插件 / Activepieces
       └─ 低置信 / 敏感：转人工
  → 组装回复 → 企微发送
  → 写会话日志与用量账本
  → （可选）注册催办定时任务
```

### 6.3 催办策略（默认，可配）

| 条件 | 动作 |
|------|------|
| 出站报价/关键问题后 T+24h 无客户回复 | 发送催办话术 A |
| T+72h 仍无回复 | 话术 B + 通知负责销售 |
| 客户已回复或销售标记关闭 | 取消后续催办 |

## 7. 功能需求详述

### 7.1 产品壳（SaaS Control Plane）

含多租户控制面与 **任务引擎（Task/Mission）**——这是相对个人 Agent 的产品差异点，必须自研（开源交付），不能指望 Coze 开箱提供。

**租户**

- 创建、停用、删除（软删）  
- 套餐绑定与配额字段  
- 状态：trial / active / suspended  

**用户与权限**

| 权限 | owner | admin | builder | viewer |
|------|-------|-------|---------|--------|
| 租户设置/白标 | ✓ | ✓ | | |
| 渠道凭证 | ✓ | ✓ | | |
| 搭建/发布 Bot | ✓ | ✓ | ✓ | |
| 知识库管理 | ✓ | ✓ | ✓ | 只读 |
| 查看用量/会话 | ✓ | ✓ | ✓ | ✓ |

**白标**

- Logo URL、产品名、主题色  
- 一期：控制台生效；二期：自定义域名  

**Bot 生命周期**

- draft → published → disabled  
- 绑定：工作流版本 ID、渠道 ID、知识库集合  

### 7.2 工厂能力（经 Coze Studio）

- Agent 与可视化工作流编排  
- 插件：HTTP / 业务 API 封装  
- 版本发布与回滚（至少保留最近 N 版）  
- 与壳的映射：一租户对应一（或有限个）Coze 工作空间  

### 7.3 知识库（RAGFlow）

- 文档上传（PDF/Word/图片扫描件优先）  
- 解析、切片、索引  
- 检索 API；回答需支持 **引用溯源**  
- 按租户隔离 dataset / 前缀  

### 7.4 自动化（Activepieces 社区版）

- Cron 催办  
- Webhook 进出  
- 与 CRM/表格同步（先通用 HTTP）  
- **不得依赖 EE 专有包**  

### 7.5 渠道网关

- 企微：官方智能机器人（长连接优先），收发文本/图片/文件（按官方能力迭代）  
- 统一内部 Channel 抽象，便于加飞书  
- 幂等、重试、死信队列  
- 密钥加密存储  

### 7.6 任务引擎（Task / Mission）— 主动性核心

| 能力 | 一期要求 |
|------|----------|
| 任务创建 | 由消息意图、工作流节点或定时规则创建 |
| 状态机 | `open → waiting → running → done / failed / handed_off` |
| 催办策略 | 可配间隔（如 T+24h / T+72h）、话术、升级对象 |
| 取消 | 客户回复、销售关闭、任务完成时取消后续催办 |
| 查询 | 控制台与 API 可按租户查看任务列表与进度 |
| 隔离 | 所有任务强制 `tenant_id`；串租视为 P0 事故 |

**主动性验收（底座过关标准）：**

1. 人在企微 @ 机器人 → 能完成多步流程  
2. **无人值守**：超时自动催、自动升级  
3. 任务列表可见长线进度  
4. 换租户数据不串  

## 8. 非功能需求

# 第二部分：技术栈与架构

## 11. 架构总图（四层底座 + 产品壳）

> **底座不是单一 Coze。** 编排用 Coze；主动与长程靠任务引擎；知识用 RAGFlow；触达用企微/飞书网关。

```
└────────────────────────────┬─────────────────────────────┘
                             │
┌────────────────────────────▼─────────────────────────────┐
│        渠道网关 channel-gateway（自研）                     │
│        鉴权 · 租户路由 · 收发 · 幂等 · 限流                 │
└────────────────────────────┬─────────────────────────────┘
                             │
┌────────────────────────────▼─────────────────────────────┐
│   产品壳 = 真正卖的产品（自研，开源可交付）                   │
│   租户·白标·配额·Bot·模板·审计·用量                         │
│   ★ 任务引擎 Task/Mission（主动长程的核心）                  │

└───────┬─────────────────┬─────────────────┬──────────────┘

        │                 │                 │
        └─────────────────┴────────┬────────┘

                    模型 API · CRM/ERP · OSS/MinIO
```

### 11.1 四层底座职责（务必分清）

| 底座 | 组件 | 职责 | 说明 |
|------|------|------|------|
| **交互底座** | 企微/飞书 + 渠道网关 | 组织内触达与被触达 | 人可调用；系统也可主动推消息 |
| **编排底座** | Coze Studio | 智能编排：复杂业务流程怎么一步步跑 | **不能单独承担**跨天任务状态 |
| **知识底座** | RAGFlow | 规格书/合同/报价等组织知识 | 回答需可溯源 |
| **主动触发底座** | Activepieces + **壳内任务引擎** | 定时、事件、长线任务持久化 | 无人值守催办/升级靠这里 |

**一句话：** 编排大脑 = Coze；主动与长程 = 任务引擎 + 调度；知识 = RAGFlow；入口 = 企微/飞书。

### 11.2 运行时：主动长程如何工作

```
事件（企微消息 / Webhook / 定时到点）
  → 渠道网关（租户路由）
  → 任务引擎：创建或推进 Mission（状态落库）
  → 需要智能步骤时 → 调用 Coze 工作流
  → 需要资料时 → 调用 RAGFlow
  → 需要到点再动 → Activepieces / 内部调度踢一脚
  → 结果回写企微/飞书 + 更新任务状态
  → 超时未完成 → 催办话术 / 升级销售 / 转人工
```

### 11.3 与 OpenClaw / 个人 Agent 的边界

| | Coze Studio | 任务引擎（自研） | OpenClaw 类 |
|--|-------------|-----------------|-------------|
| 定位 | 可视化编排工厂 | 组织任务状态与主动推进 | 个人/小团队助理运行时 |
| 本项目 | **编排底座（默认）** | **主动长程必选** | 可选通道参考，**不替代**上两者 |
| 多租户 | 由壳映射 workspace | 强制 tenant_id | 单信任域，不宜多租户混部 |

## 12. 技术选型明细

### 12.1 开源引擎

| 组件 | 协议 | 用途 | 注意 |
|------|------|------|------|
| Coze Studio | Apache 2.0 | 工厂核心 | 开源版缺完整企业多租户/SSO/集群 → 壳补 |

### 12.2 排除清单（License）

| 组件 | 原因 |
|------|------|
| Dify | 禁对外多租户；前端禁去 Logo |
| n8n | Sustainable Use：禁白标/有偿转售托管 |
| FastGPT | 类 Dify 附加条款 |
| MaxKB | GPL-3.0，闭源白标/分发风险高 |

### 12.3 自研部分建议栈

| 模块 | 建议技术 | 说明 |
|------|----------|------|
| API（含任务引擎） | Go（Gin/Hertz）或 NestJS | 团队熟悉优先；Mission 状态机与租户 API 同仓 |
| 控制台 | React + TypeScript + Ant Design Pro | 租户后台 |
| DB | PostgreSQL | 租户与业务元数据 |
| 缓存/队列 | Redis +（可选）NATS/RabbitMQ | 会话、限流、异步 |
| 对象存储 | MinIO / 云 OSS | 文档与导出 |
| 入口 | Nginx / Caddy / Traefik | TLS、域名 |
| 部署一期 | Docker Compose | PoC 与首批 |
| 部署二期 | Kubernetes | 规模化 |
| 租户隔离一期 | 逻辑隔离 + 引擎侧 workspace 映射 | 二期再硬隔离 |

### 12.4 模型

- 对话：DeepSeek / 通义 / GLM 等 OpenAI 兼容接口  
- Embedding：BGE 或云 Embedding  
- 按租户配置 API Key 或平台统一 Key + 分账

## C. 相关结论备忘

- 底座四层：**交互（企微网关）+ 编排（Coze）+ 知识（RAGFlow）+ 主动长程（任务引擎 + Activepieces）**  
- 产品壳含任务引擎，这是相对个人 Agent 的核心差异  
- 不做白标内核：Dify / n8n / FastGPT / MaxKB  
- OpenClaw：通道参考，非工厂基座，不替代任务引擎  
- 首发闭环：询价 → RAG → 报价/回复 → 企微 → **任务引擎催办/升级**
