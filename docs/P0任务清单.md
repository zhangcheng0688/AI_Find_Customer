# P0 任务清单（3–5 天）

目标：仓库可跑、边界清晰、任务引擎有骨架；**还不要求**真连企微（那是 P1）。

## P0-1 仓库骨架

- [ ] Monorepo 目录按简报创建
- [ ] README：如何启动、架构一句话、License 红线
- [ ] `docs/PRD与技术栈.md` 放入仓库
- [ ] `docs/license-compliance.md`：允许/禁止依赖列表

**完成标准：** 克隆后目录一眼能懂；红线写进 docs。

## P0-2 Docker Compose 依赖

- [ ] Postgres、Redis、MinIO
- [ ] 占位服务或注释好的 Coze Studio / RAGFlow / Activepieces 接入说明（能拉起的尽量拉起；暂起不来的写明版本与后续 issue）
- [ ] `.env.example`

**完成标准：** `docker compose up -d` 至少核心中间件健康；文档写清端口。

## P0-3 API 壳 + Mission 模型

- [ ] 健康检查 `GET /health`
- [ ] Tenant / User 最小模型（可先单租户 seed）
- [ ] **Mission**：字段含 tenant_id, bot_id, type, status, due_at, assignee, context_json, last_action_at, cancel_reason
- [ ] 状态机：open → waiting → running → done | failed | handed_off
- [ ] CRUD API：创建/查询/更新状态/取消
- [ ] 所有查询强制 tenant_id

**完成标准：** 用 curl/httpie 能创建一条任务并推进状态；单测或脚本覆盖状态流转。

## P0-4 渠道网关骨架

- [ ] `channel-gateway` 空服务：接收「入站消息」内部 JSON、校验 tenant 映射占位、调用 api 创建 mission 或转发编排（编排可 mock）
- [ ] 幂等 key 中间件占位
- [ ] 尚不接真实企微也可，用 `POST /dev/ingest` 模拟企微消息

**完成标准：** 模拟一条询价消息 → 产生 Mission → 返回 mock 回复。

## P0-5 控制台极简页（可选但推荐）

- [ ] 登录可先写死 dev
- [ ] 任务列表页：按状态筛选
- [ ] 白标占位：Logo/标题读配置

**完成标准：** 浏览器能看到 P0-3 创建的任务。

## P0 总验收

- [ ] Compose 中间件 OK
- [ ] Mission API OK
- [ ] 模拟入站 → 任务落库
- [ ] 文档含：如何本地跑、红线、下一步 P1（企微）需要的环境变量

## 明确不做（P0）

真企微、真 Coze 编排、真 RAG 灌库、多租户计费、飞书、美化 UI。
