# 海外拓客 / 官网助理 / 社媒自动化 — 解决方案草案

本文对照客户需求表（P1 海外拓客全域整合、P2 官网 AI 智能助理、P3 海外社媒自动化），结合当前仓库 **AI Hunter** 已有能力，给出可落地的方案边界、推荐架构与分期。

客户侧 CRM / 数据分析明确不在开发范围内；本方案只覆盖线索生产、清洗、导出，以及官网接待与社媒分发。

---

## 1. 结论先行

| 优先级 | 建议 | 原因 |
| --- | --- | --- |
| **P1 先做** | 在现有 Hunt 流水线上扩成「HS 码找进口商 → 官网深挖 → LLM 清洗 → 导出」 | 仓库已有海关证据路由、官网抓取、联系人抽取、评分与 CSV/JSONL 导出，缺口主要是**发现方向反转**和**清洗规则产品化** |
| **P2 并行轻量** | 做可嵌入的 RAG 接待组件，不绑死 WordPress | `slam.systems` 当前是静态站，不是 WP；widget 可同时挂静态站和 WP |
| **P3 后做且降级** | 只做官方 OAuth 发帖 + 公开内容筛客；**不做自动点赞/关注** | 点赞关注属于平台 ToS 高风险能力，账号被封后无法合同兜底 |

三条硬边界建议写进方案/合同，避免后期扯皮：

1. **只采集公开信息**，不破解、不绕过登录墙、不买盗用账号、不 SMTP 探测邮箱是否存在。
2. **海关企业级明细不是全球公开数据**。美国提单相对公开；欧盟/多数国家只有汇总统计。企业级全球覆盖必须走**授权商业数据源**，不能靠爬 ImportGenius / Panjiva / Volza。
3. **社媒互动（赞/粉）不自动化**。分发走官方 API；互动由销售人工或官方允许的私信接口完成。

## 2. 现有系统能接住什么

当前主链路：

```
Insight → KeywordGen → Search → LeadExtract → Evaluate →（可选）EmailCraft → Campaign
```

和需求表的对应关系：

| 需求点 | 现状 | 差距 |
| --- | --- | --- |
| 海关数据 | `tools/customs_router.py` 已对接 ImportGenius / Volza / Trademo / Panjiva / Zauba 等**检索页**，给**已知公司**补贸易证据 | 方向反了：现在是「公司 → 海关」；需求是「HS/国家/频次 → 活跃进口商名单」 |
| 官网深挖 | Jina Reader + 联系页发现（Contact / About / Team / Impressum，最多 3 条）+ 邮箱/电话/社媒正则 | 没有生产级 Playwright；动态站、采购页、多层站图谱不够 |
| LLM 清洗 | `fit_score` / `contactability_score` / `priority_tier`，会排除同类制造商 | 没有货代/报关行分类、破产/停业、空号邮箱、意图评级、规则可配置 |
| 数据导出 | Hunt 结果可落库；邮件链路独立 | 客户要所有权清晰的 CSV/JSONL 批量导出（这块补齐成本低） |
| 官网 AI | 无 | 新产品 |
| 社媒分发/筛客 | 只会从页面**抽取**社媒 URL | 无发帖、无监听、无互动 |

仓库里已有海关抓取策略对比脚本（raw / Jina / Playwright），Playwright **未进入生产依赖**。官网侧 `slam-systems-site/` 是静态 HTML/CSS/JS，不是 WordPress。

## 3. P1：海外拓客全域整合

### 3.1 目标形态

客户输入：产品 HS 码（或产品名）、目标采购国、时间窗、最低进口频次。

系统输出：经过清洗的活跃进口商表，字段至少包括：

- 公司名、国家、官网、决策人、邮箱/电话/社媒
- 海关信号：HS、最近活跃期、进口频次/货量档、贸易伙伴国、证据 URL
- 清洗标签：`importer` / `forwarder` / `peer` / `inactive` / `unknown`
- 意图评级：`A/B/C`
- 全程可溯源的 `evidence[]`

客户自己导入 CRM。我们提供导出，不接他们的 CRM。

### 3.2 推荐流水线

```
HS / 产品 / 国家 / 频次
        │
        ▼
┌───────────────────┐
│  Importer Discovery │  授权海关 API + 公开官方源
└─────────┬─────────┘
          │ 候选进口商（公司名 + 国家 + 贸易信号）
          ▼
┌───────────────────┐
│  Website Graph Crawl │  公开页、多层、动态渲染兜底
└─────────┬─────────┘
          │ 联系人 / 采购页 / 团队页
          ▼
┌───────────────────┐
│  LLM Clean + Score  │  货代/停业/空邮箱/同行；意图评级
└─────────┬─────────┘
          │
          ▼
     CSV / JSONL 导出（客户拥有）
```

现有 Search → LeadExtract 继续用，但前面加一个 **Importer Discovery** 节点，后面把 Evaluate 扩成可配置规则引擎。

### 3.3 海关数据：必须分层，不能「全球公开爬」

#### A. 公开官方源（合规优先，覆盖有限）

| 源 | 能拿到什么 | 更新 | 限制 |
| --- | --- | --- | --- |
| 美国 CBP / AMS 提单类公开聚合 | 进口商名、部分产品描述、日期、港口 | 接近日更（视供应商） | 主要是进入美国的货 |
| UN Comtrade / EU COMEXT | HS × 国家的**汇总**进出口 | 月/年 | **没有企业名单** |
| 各国开放公司注册（如 OpenCorporates、德国 Unternehmensregister 公开页） | 存续、地址、部分高管 | 不等 | 不是海关，只做停业校验 |

结论：若客户要的是「德国/中东/东南亚的活跃进口商名单」，**单靠公开爬取做不到企业级覆盖**。必须在售前把这句话讲清楚。

#### B. 授权商业源（做企业级名单的正经路径）

按客户目标市场采购其一或组合，走合同 API，不爬对方前台：

- 美线：ImportYeti / ImportGenius / Panjiva 等 **API 或授权 bulk**
- 全球 HS 贸易：Volza / Trademo / Trade Atlas 的授权接口
- 仅要宏观验证：UN Comtrade 做「这个 HS 在这个国家有没有量」

现有 `customs_router.py` 可保留为 **证据补全**（用搜索引擎命中的公开摘要页），但 **Discovery 名单不能依赖爬这些站点**。改版后的路由器应变成：

1. 有 API key → 走授权接口
2. 无 key → 只查公开官方源，并明确返回 `coverage=limited`
3. 付费站点前台 → 不再作为主路径

#### C. 更新周期（建议写进 SLA）

- 公开源：按上游，通常 T+1 到 T+7
- 商业 API：跟随供应商（常见周更/月更）
- 我们侧：任务触发时拉增量；不做 7×24 全库镜像（成本与授权都不划算）

### 3.4 官网深挖

抓取瀑布，按成本从低到高：

1. **httpx 直连** — 静态站、Impressum、多数企业站
2. **Jina Reader** — 已有，适合中等动态页
3. **无头浏览器（Playwright / Browserless）** — JS 渲染、采购门户、SPA；只对 1/2 失败或明确动态的 URL 启用

站内策略（遵守 `robots.txt` + Crawl-Delay，只跟同域公开链）：

- 种子：首页
- 优先路径：`contact` / `about` / `team` / `imprint` / `impressum` / `procurement` / `purchasing` / `suppliers` / `rfq`
- 深度：默认 2～3 层，单站 URL 上限（建议 12）
- 抽取：邮箱、电话、WhatsApp、LinkedIn、办公地址、采购邮箱、决策人姓名/职位

反爬与 IP：

- 默认：自有出口 IP + 低并发 + 退避
- 升级：住宅代理池（仅用于公开页；账号密码墙直接放弃）
- 被封：记入任务日志，换代理或跳过该站，**不绕过验证码/登录**
- 责任：合同写明「采集公开信息；因目标站封禁导致该条线索缺失不视为违约；禁止用于入侵」

网站改版维护：

- 抽取以「通用结构 + LLM」为主，不为单站写死 XPath
- 单站选择器维护不进入标准报价；只有客户指定必须盯死的重点站点才单独立项

### 3.5 LLM 清洗与意图评级

建议做成**规则 + 模型**两段，规则可配置，模型只填证据不足的空。

| 过滤器 | 判定方式 | 可否自定义 |
| --- | --- | --- |
| 货代 / 报关 / 物流 | 关键词 + 官网业务描述分类（forwarder / 3PL / customs broker） | 是，词表可配 |
| 同行 / 竞品 | 已有「同类制造商 disqualify」；扩成产品重叠度 | 是 |
| 空邮箱 | 语法 + MX；**不做 SMTP RCPT**（容易被当spam） | MX 失败可丢弃或降权 |
| 停业 / 破产 | 注册处状态、官网过期、海关最近活跃日超过 N 个月 | N 与名录源可配 |
| 活跃进口商 | 时间窗内记录次数 ≥ 阈值 | 阈值可配 |
| 意图评级 A/B/C | 海关频次 + 采购页/RFQ + 决策人完整度 + 联系方式质量 | 权重可配 |

「破产/停业」**不能保证**。诚实口径：

- 有注册状态 → `registry_status`
- 无注册状态但海关 >N 个月无记录且官网无响应 → `likely_inactive`
- 其余 → `unknown`，不假装判定

客户可在任务里开关上述规则，导出带标签，让他们在 CRM 里再筛。

### 3.6 数据权属与导出

- 原始公开网页快照：任务级短期缓存，到期删除
- 结构化线索：客户导出后归客户；我们库内按租户隔离
- 商业海关源：受上游合同约束，通常**禁止转售原始提单库**，只允许客户自用线索
- 导出：CSV + JSONL，字段与 `evidence` 一并给出，方便他们自己做分析

## 4. P2：官网 AI 智能助理

### 4.1 和现状的错位

需求写的是 WordPress；当前 `slam.systems` 是静态站。方案应按 **「一段 JS，两种宿主」** 做，避免先逼客户迁 WP。

### 4.2 能力拆分

1. **7×24 多语接待（RAG）**
   - 知识库：产品手册、现有官网页面、FAQ、报价边界
   - 回答必须带来源片段；检索不到就说「需要人工」，禁止编型号/价格/认证
   - 语言：先 DE / EN / ZH，按页面 `lang` 或访客选择
2. **线索挖掘**
   - 从对话抽：产品线、应用场景、预算区间、采购周期、国家、联系方式
   - 意图分：浏览 / 询价 / 项目
3. **销售同步**
   - 高意向会话推到内部 webhook（邮件 / 企业微信 / 飞书）
   - WhatsApp 一键：走 **Meta Cloud API**，不共享个人 WhatsApp 密码
4. **报表**
   - 会话数、被知识库拦住的拒答数、高意向数、转人工数
   - 不做客户要的 CRM 分析
5. **SEO / GEO**
   - **与聊天组件解耦**。聊天脚本 `defer`/`async`，不改业务交互
   - SEO 另做：title/description、结构化数据、sitemap、（若多语）hreflang
   - 合同可写：「小部件不修改现有下单/表单逻辑；SEO 变更以清单为准，可回滚」

### 4.3 部署与知识库

| 问题 | 建议答案 |
| --- | --- |
| 嵌入 WP | 短代码 / 插件插一段 script，或主题 footer；静态站同样一段 script |
| 上线时间 | 知识库就绪后，嵌入本身是小时级 |
| 客户能否自更新 | 后台上传 PDF/Markdown + 官网 URL 再抓取；变更后重建索引 |
| 能否锁死知识库 | 能。system prompt + 无命中拒答 + 不允许联网补充 |
| GDPR | EU 区部署、Cookie/对话同意、DPA、对话默认 30 天、客户可导出/删除 |
| 改版维护 | 组件与主题皮肤分离；大改版只可能要调 CSS。SEO 效果用 Search Console / 索引报告验收，不承诺排名 |

## 5. P3：海外社媒自动化（降级方案）

### 5.1 建议做

**分发（OAuth）**

- Facebook / Instagram：Meta Graph
- LinkedIn：官方 Marketing / Community（视产品形态申请）
- YouTube：YouTube Data API 上传
- X：官方 API（配额贵，单列报价）
- 一键绑定 / 一键解绑；**不收集密码**
- 媒体限制完全跟随各官方 API（时长、体积、格式），后台展示限额

**筛客（公开内容 + LLM）**

- 关键词组客户可配
- YouTube：官方字幕 / Captions API，不够再对**已授权或明确公开**的音轨做 STT
- 图文：平台公开搜索 API 或客户自己主页评论；多模态 LLM 做意图，而不是页面 RPA
- 命中结果进线索池，供 P1 清洗复用

### 5.2 明确不做（或仅人工）

自动赞、自动关注、云手机、模拟真人滑动：

- 各平台 ToS 明确限制
- 封号后没有稳定「解封方案」，无法写进 SLA
- 若客户坚持，只提供：**名单 + 深链到官方 App，销售人工点**；可加每日上限提醒，但系统不代点

底层技术口径：分发与检索 **API**；不做 RPA/云手机。

## 6. 对需求表「必问问题」的建议口径

### P1

- **覆盖哪些国家、更新周期？** 企业级名单取决于买哪家海关 API。公开源以美线提单为主；其它国家先用汇总数据验证市场，再决定是否采购该国商业库。更新跟随上游，任务触发拉取。
- **JS 动态站、反爬、IP？** 三级瀑布（直连 → Jina → Playwright）+ 可选住宅代理；遵守 robots；验证码/登录墙跳过。
- **网站改版维护费？** 通用抽取含在年维护里；指定站点死 XPath 另计。
- **数据能否导出、归谁？** 结构化线索可导出，归客户自用；上游海关原始库按供应商协议，不转售。
- **如何判定破产/停业、规则能否自定义？** 注册状态 + 海关活跃窗口 + 官网可达；三档标签；规则可配。不能 100% 判定。
- **是否只采公开信息？封 IP 责任？** 只采公开页。封禁导致单条缺失不视为系统故障；不提供绕过手段。

### P2

- WP 嵌入：一段脚本，小时级。静态站同样支持。
- 知识库客户可自己更新。
- 语言分期上；回答锁知识库。
- GDPR：EU 托管 + DPA + 可删可导。
- SEO 与聊天分离；「不改原功能」可按清单写进合同。
- 效果验收用索引/富结果，不承诺搜索排名。

### P3

- 分发：OAuth，可解绑；YouTube 走官方 API；文件限制跟官方。
- 筛客：可配关键词组；STT 语言与准确率随模型和字幕质量变化，需试点后给数字。
- 风控：API，不 RPA；互动不自动；封号无赔偿承诺。

## 7. 建议分期（按技术依赖，不按日历）

### 一期：P1 可用闭环（对客户价值最大）

1. Importer Discovery：至少接通 **一条**授权海关源 + 美线公开源；输入 HS/国家/频次
2. 官网图谱爬取：现有 Jina 加深 + Playwright 兜底 + robots
3. 清洗：货代/同行/MX/活跃窗口 + A/B/C；规则配置
4. 导出 CSV/JSONL（含证据）
5. 售前说清覆盖范围，避免「全球公开海关」预期

现有 Hunt / 邮件开发信可继续作为一期的可选增值，但不是客户 P1 必选项。

### 二期：P2 官网接待

- RAG widget + 知识库后台 + WhatsApp Cloud 深链/会话通知
- 接在静态 `slam.systems`（或 WP，若他们同时有 WP 站）
- 基础咨询/转化统计

### 三期：P3 发帖与筛客

- OAuth 多平台分发
- 关键词 + LLM 筛客进 P1 池
- 不交付自动赞粉

## 8. 需要客户拍板的 6 件事

在开工前建议书面确认，否则 P1 范围会漂：

1. **目标采购国清单**（决定买哪家海关库，以及公开源是否够用）
2. **是否接受「无商业库 = 无企业级名单」**（尤其是欧陆）
3. **HS 码样本 + 排除的货代关键词**（便于一期规则）
4. **官网到底是 WP 还是当前静态站**，P2 挂在哪
5. **P3 能否接受「只发帖 + 筛客、不自动互动」**
6. **数据托管地区**（GDPR / 中国出海常见是 EU 或客户自有 VPC）

## 9. 和本仓库的落点（供内部实现时对照）

一期若在本仓库演进，较自然的改动点：

- 新建 `agents/importer_discovery_agent.py`：HS → 候选进口商
- 扩展 `tools/customs_router.py`：API provider 优先，搜索页降为证据
- 扩展 `tools/jina_reader.py` / 新增 `tools/browser_fetch.py`：动态页兜底
- 扩展 `tools/contact_extractor.py`：采购页路径、决策人块
- 扩展 Lead 模型：`company_type`、`intent_tier`、`activity_window`、`filter_tags`
- 新增导出 API：`GET /api/v1/hunts/{id}/export`
- P2 / P3 建议**独立服务**，不要塞进 Hunt 图里

未拍板前，不在本仓库实现 P3 互动，也不去爬付费海关前台。
